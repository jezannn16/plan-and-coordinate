# Plan and Coordinate

Route the request to the right mode. Load only that mode's reference guide unless the user asks for a combined workflow.

| Request | Mode guide |
|---|---|
| Turn a roadmap or high-level specification into per-release, task-by-task plans | Read references/roadmap-expansion.md |
| Expand an already phased vision into one executable plan per release | Read references/phased-release-decomposition.md |
| Assign tasks and track ownership or progress across multiple contributors | Read references/agent-coordination.md |

## Routing rules

- Preserve phases and scope already defined by the user. Do not invent releases to fill gaps.
- If the plan is explicitly phased and each phase has scope or completion criteria, use the phased-release mode.
- If the request is to expand a roadmap into implementation-ready release files, use the roadmap-expansion mode.
- Create a coordination board only when the user asks to coordinate contributors or track parallel work. A plan by itself does not imply a board.
- For combined requests, finish or confirm the plan structure before distributing tasks. Follow any stop conditions in the selected guide.

## Output language

Write in the language requested by the user, or match the language of the request.
